# Vainah VPN Desktop — Windows + macOS

**v0.5.2 — улучшенный импорт H1Cloud/VLESS на Windows; проверка защиты VPN-трафика ещё не завершена.**

### Windows: исправления 0.5.2

- Импорт HTTPS-подписки с VLESS-списком, Base64/Base64url (включая без `=`),
  JSON-массивами и документами sing-box/Xray с `outbounds`, `profiles`,
  `servers`, `nodes`, `links`.
- Принимаются корректные VLESS + TCP/RAW + REALITY, а неизвестные протоколы
  безопасно пропускаются. HTTPS редиректы допускаются только внутри того же
  origin, с проверенным публичным IP; ключи не переходят на другие домены.
- Исправлена ложная ошибка «неверная ссылка»: корректный VLESS-ключ можно
  добавить даже тогда, когда проверка встроенным sing-box пока недоступна.
  **Импорт не равен подключению VPN**. Запуск двигателя требует отдельной
  проверки конфигурации и системного туннеля.
- Каждый установщик имеет собственную версию сборки (0.5.2-preview.N).

Нужна **HTTPS-ссылка подписки** или полноценный **vless://** ключ;
сырой JSON при необходимости можно открыть через отдельный выбор файла.
Никогда не публикуйте личные VPN-ссылки и API-токены в Issues или логах.


Новые приложения дополняют уже существующие Android / iOS и веб-сайт
Vainah VPN. Настоящий H1Cloud/VLESS-туннель и авторизация внутри desktop
клиента **не реализованы**. Тестовая версия не является VPN и не
защищает трафик. Она не должна показывать «подключено».

## Что уже умеет

- Русский интерфейс по дизайну сайта: фирменный логотип V,
  та же палитра, крупная кнопка, тарифы и доступная навигация.
- Понятный старт из трёх шагов, подсказки, FAQ, инструкции по устройствам.
- Поиск H1Cloud-локаций, обновление HTTPS-подписки каждые 5 минут в состоянии OFF.
- Безопасный показ названия сервера вместо URL, IP или UUID узла.
- Состояние оплаты и сверка тарифов с сервером: заказы не создаются в приложении.
- **6 тарифов с ценами сайта** из зафиксированного общего каталога.
  Отдельный тест проверяет совпадение данных с сервером.
- Только разрешённые страницы сайта открываются во внешнем браузере.
- Нет полей для VPN-секретов, их хранения, удалённых скриптов,
  платежей, аналитики или скрытых системных прав.
- Windows: Electron/Chromium, NSIS x64, закреплённая официальная библиотека
  Wintun 0.14.1. GitHub проверяет SHA‑256 ZIP, подпись DLL и включает
  лицензию распространения. При отсутствии драйвера запуск запрещён.
- macOS: Electron/Chromium, DMG Intel x64 + Apple Silicon arm64.

## Как запустить локально

В каталоге `desktop`:

```bash
npm install
npm start
```

Для сборки и тестов:

```bash
npm test
npm run dist:win   # только на Windows
npm run dist:mac   # только на macOS
```

Автоматические builds в `.github/workflows/desktop-preview.yml`.
CI публикует только **GitHub prerelease**:
`desktop-windows-preview-v0.5.0-run-...`. Не публикует в магазины
и не трогает Netlify Production.

**Ограничение тестовой сборки:** установщики пока без
коммерческой цифровой подписи / Apple notarization. Система может
не разрешить их запуск. Не обходите предупреждения безопасности:
для надёжного массового распространения нужны подпись, notarization
и проверенные официальные каналы распространения.

## Архитектура и безопасное расширение

```text
src/main.cjs      Electron main: главное окно, закрытый список внешних ссылок, IPC
src/preload.cjs   Минимальный изолированный API; только getInfo/Plans/Tunnel/OpenOfficial
ui/index.html     Семантические разделы, предупреждение о неработающем туннеле
ui/styles.css     Собственные токены и адаптация фирменного сайта
ui/app.js         Навигация, фильтр тарифов, диалог «пока не подключается»
shared/catalog.cjs 6 планов, сравниваемых с сервером в тестах
shared/official.cjs Закрытый список оригинальных страниц Netlify
```

Electron рендеринг локальный, с жёстким CSP, без
`nodeIntegration`, с `contextIsolation`, `sandbox` и запретом
запроса разрешений. IPC проверяет отправителя, ссылки проходят
строгий whitelist.

## Что нужно для настоящего большого проекта

1. Встроить совместимый с конкретной конфигурацией H1Cloud/VLESS
   реальный движок и системное сетевое расширение. Для Windows
   понадобится проверенная маршрутизация TUN/Wintun и безопасный
   жизненный цикл драйвера; для macOS — Packet Tunnel
   NetworkExtension с разрешениями и подписью.
2. Протестировать TCP/UDP, DNS/IPv6, маршруты, исключения,
   обрывы сети, утечки, безопасность и скорость на устройствах.
3. Сделать безопасный вход через существующие провайдеры,
   owner-scoped API доступа к реально оплаченным подпискам
   и привязку аккаунтов с подтверждением двух сторон.
4. Централизовать конфигурации тарифов, проверку доступности,
   обновления, локализацию и версионирование.
5. Снабдить каждую платформу проверенной подписью; запустить
   закрытое тестирование перед массовым выпуском.

**Никогда не выдавайте отсутствие VPN-движка за защищённое соединение.**
