# Vainah VPN — Telegram, Clerk (почта и телефон), Яндекс ID

## Важное
Vainah VPN — **уже существующий** статический HTML/JavaScript-сайт на Netlify
с Netlify Functions. Не создавайте второй проект на Vite, Next.js или React:
вход через Clerk подключается через [официальный CDN ClerkJS](https://clerk.com/docs/js-frontend/getting-started/quickstart).

**Пока не переключён production, не объединять PR и не запускать Deploy.**
Работоспособность кода в GitHub не подтверждает работоспособность внешнего
Clerk на актуальном домене без настройки провайдера.

## 1. Оставить Telegram
Проверьте Netlify:
```env
TELEGRAM_BOT_TOKEN=
SESSION_SIGNING_KEY=
PUBLIC_SITE_ORIGIN=https://vainahvpnbot0.netlify.app
```
В `@BotFather` разрешите актуальный домен Login Widget. Оставлена
кнопка повторной загрузки виджета. Telegram-бот может продавать подписки
отдельно; кнопка покупки через бота на сайте **не добавлена**.

## 2. Clerk для электронной почты и телефона
В `dashboard.clerk.com` → нужное приложение → **Configure** →
**User & authentication**:

1. Email: разрешить вход с подтверждением кода.
2. Phone: включить OTP по SMS только при наличии права использовать
   SMS в нужном тарифе Clerk. В режиме Development функция может
   работать для тестирования, но **для рабочего Production необходим
   платный план**. Не пытайтесь обходить эти ограничения.
3. SMS → Settings: явно разрешить те страны, для которых отправка кодов
   действительно необходима. Не открывайте весь мир: могут быть расходы.
4. Проверьте ограничения на отправку кодов, защиту от спама и лимиты.

У Clerk сейчас на скриншотах **Development**. Для публичного
`vainahvpnbot0.netlify.app` нужны настоящие ключи
**Production** (`pk_live_…` и `sk_live_…`).
Подключение SMS к платёжной учётной записи проводит совершеннолетний
владелец, если этого требуют правила сервиса.

В Netlify → Environment variables:
```env
CLERK_PUBLISHABLE_KEY=
CLERK_SECRET_KEY=
```
Ключ Publishable публичный по назначению; Secret Key должен оставаться
**только в Netlify**, никогда не отправляйте его в чат и GitHub.

На сайте есть общая форма Clerk на вкладках «Почта» и «Телефон»:
при выборе конкретного способа Clerk сам показывает доступные в
приложении способы входа. Если SMS не настроен, он не будет доступен
в официальной форме. Сайт не запрашивает SMS-коды через собственный
сервер и не использует старую Twilio-форму на этих вкладках.

### Что делает сервер
`clerk-auth-config` возвращает только Publishable Key, если
production-конфигурация полная и домен совпадает с `PUBLIC_SITE_ORIGIN`.

`clerk-session` принимает Clerk JWT **только** через
`Authorization: Bearer` и проверяет его при помощи
`@clerk/backend` с `authorizedParties`, типом session token и
обязательным `Origin`, после чего выдаёт собственную
HttpOnly/Secure/SameSite cookie, в которой содержится только
привязанный к Clerk ID **отдельный** идентификатор сессии.

Ключи Development `pk_test_`/`sk_test_` преднамеренно
**не включают** данный вход на публичном рабочем домене.

## 3. Яндекс ID
Оставлен прежний OAuth со state и PKCE.
Netlify:
```env
YANDEX_CLIENT_ID=
YANDEX_CLIENT_SECRET=
```
Redirect URI:
`https://vainahvpnbot0.netlify.app/.netlify/functions/yandex-callback`

## 4. Заказы и безопасность
VPN-история в базе по-прежнему привязана к подтверждённому
`telegram_id`. Сессии Clerk и Яндекса **не являются Telegram-сессией**
и не могут видеть/выкупать/продлевать Telegram-заказы или личные
VPN-ссылки. Для объединения нужна будущая отдельная функция,
подтверждающая владение **обоими** аккаунтами.

`checkoutReady()` остаётся `false`; реальные платежи сайта
не включаются этим изменением.

## 5. Перед публикацией
- Дождитесь зелёных GitHub Actions на PR.
- Закончив настройки Clerk Production, проверьте публичный домен.
- Только после этого согласованно объедините PR и выполните Deploy.
- Откройте `/account.html`, проверьте Telegram, email-код, и Яндекс.
  Для SMS — только если функция доступна и разрешена в Production.
- Проверяйте, что вход через Clerk не показывает историю
  Telegram-покупок до безопасного подтверждённого связывания.
