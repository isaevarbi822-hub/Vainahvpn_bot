# Vainah VPN — безопасный вход: Telegram, телефон, email, Яндекс

Текущий сайт: `https://vainahvpnbot0.netlify.app`. Если домен меняется,
обновите `PUBLIC_SITE_ORIGIN`, разрешённые адреса в Telegram и
Redirect URI приложения Яндекс. Секреты нельзя отправлять в чат, GitHub,
клиентский JavaScript или скриншоты.

## Telegram Login
- Netlify: `TELEGRAM_BOT_TOKEN`, `SESSION_SIGNING_KEY` (не короче 32 случайных
  символов), `PUBLIC_SITE_ORIGIN=https://vainahvpnbot0.netlify.app`.
- В BotFather разрешить актуальный адрес сайта для Telegram Login Widget.
- На `account.html` есть кнопка «Повторить загрузку»: она помогает отличить
  проблему внешнего виджета от ошибки серверной проверки.
- Вход проверяется **на сервере** по HMAC подписи Telegram. Произвольные
  `username` и Telegram ID не принимаются.
- Telegram-бот может продавать свои подписки отдельно. Никакой кнопки
  покупки в боте на странице авторизации нет.

## Вход по телефону и электронной почте
Для обоих способов используется **Twilio Verify v2**, чтобы не хранить
одноразовые коды на сайте. Настраивает владелец аккаунтов сервисов,
при необходимости — с уполномоченным совершеннолетним.

Netlify environment variables:
```env
TWILIO_ACCOUNT_SID=
TWILIO_AUTH_TOKEN=
TWILIO_VERIFY_SERVICE_SID=
```

- Телефон: SMS-канал, формат E.164 (`+47…`, `+7…` и т. д.).
- Email: email-канал **того же Twilio Verify Service**, для которого нужно
  подключить поддерживаемого отправителя (например, SendGrid) в самом Twilio
  Verify. Один лишь сервис SMS **не включает email автоматически**.
- До настоящей настройки провайдера форма явно показывает,
  что способ ещё не доступен; фальшивые коды и тестовые входы не предусмотрены.
- Для production включите rate limits / Fraud Guard / региональные ограничения
  Twilio Verify, чтобы избежать массовых платных отправок SMS.
- Сервер устанавливает подписанный HttpOnly challenge cookie на 10 минут,
  который привязан к **конкретному** адресу/номеру; код проверяется Twilio.
- Cookie не содержит пароль, номер, email или OTP. Дополнительная
  cookie ограничивает повторный запрос из одного браузера примерно на минуту.
  Это НЕ замена rate limits на стороне Twilio.

## Вход с Яндекс ID
Зарегистрируйте приложение типа **«Для входа на сторонний сервис»**
в [Яндекс OAuth](https://oauth.yandex.ru/); разрешение `login:info`.

Netlify:
```env
YANDEX_CLIENT_ID=
YANDEX_CLIENT_SECRET=
```

**Redirect URI**, который нужно зарегистрировать в Яндекс:
```text
https://vainahvpnbot0.netlify.app/.netlify/functions/yandex-callback
```

Здесь используется OAuth 2.0 Authorization Code с PKCE и подписанной
короткоживущей state-cookie, а не самостоятельная форма для ввода
пароля Яндекса. Сервер также проверяет `client_id` в ответе API Яндекс.

## Разграничение доступа (важно)

Текущая таблица VPN-заказов имеет ключ `telegram_id`.
Новые способы входа создают **отдельную подтверждённую сессию** на сайте,
но **не получают доступ к существующим Telegram-заказам**, VPN-ссылкам,
продлению или RollyPay checkout по одному только номеру/email/Яндекс ID.
Для полноценной единой истории нужна отдельная миграция базы
и безопасная привязка уже подтверждённых аккаунтов, которая в эту
версию не включена. Это преднамеренное ограничение безопасности,
а не ошибка.

После установки переменных запустите новый Deploy.
Ни на одном из шагов **не включается** `checkoutReady()`: реальные платежи
на сайте по-прежнему заблокированы до проверки провайдера и выдачи.
