# Vainah VPN — Python sandbox API

Отдельный сервер на Python + FastAPI для локальной разработки. Не заменяет действующий сайт Netlify, приложение или VPN-движок.

## Запуск в Windows PowerShell

В папке python-backend запусти:

    py -3 -m venv .venv
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt
    .\.venv\Scripts\python.exe -m app.main

В консоли появятся адрес http://127.0.0.1:8765/docs и Local test token.

Открой Swagger в браузере, нажми Authorize и введи локальный токен в X-Dev-Token.

Далее выполни:

1. GET /health — покажет режим mock.
2. POST /sandbox/start — создаст условный заказ на 10 рублей. Скопируй order_id.
3. POST /sandbox/{order_id}/simulate — передай JSON {"status":"paid"} для имитации успешной оплаты.
4. GET /sandbox/{order_id} — покажет результат.

Это локальный симулятор: он никогда не отправляет данные в RollyPay, не списывает средства и не выдаёт VPN. Не нужны никакие секретные ключи. Заказы живут только в памяти процесса. При перезапуске данные исчезают.

## Автоматические тесты

    .\.venv\Scripts\python.exe -m pytest -q

Тесты используют фальшивые HTTP-ответы RollyPay, проверяют обязательное поле test:true, новый X-Nonce, строгую проверку суммы и ссылки и безопасные сообщения об ошибках. Настоящих запросов на оплату они не отправляют.

## Отдельный режим обращения к настоящему sandbox (только для уполномоченного оператора кассы)

Этот режим выключен по умолчанию и требует разрешённого существующего мерчант-аккаунта, управляемого лицом, соответствующим условиям RollyPay. Не обходи правила регистрации или возрастные ограничения сервиса.

В той же консоли PowerShell перед запуском можно задать:

    $env:VAINAH_SANDBOX_MODE = 'provider'
    $env:VAINAH_ALLOW_PROVIDER_TEST_ONLY = 'enabled'
    $env:ROLLYPAY_API_KEY = '<секретный ключ из разрешённой кассы>'
    .\.venv\Scripts\python.exe -m app.main

Не публикуй API-ключ в GitHub или сообщениях. Все запросы создания счета содержат test:true и сумму ровно 10.00 RUB; реальные платежи этот сервис не создаёт.

Ответ провайдера должен явно подтвердить test:true и environment:sandbox, иначе даже pay_url не выдаётся. Официальная документация показывает, что поля sandbox могут отсутствовать в примере ответа. В таком случае сервис намеренно остановит запрос ошибкой PROVIDER_SANDBOX_NOT_CONFIRMED, пока оператор не подтвердит контракт RollyPay.

Рабочее приложение Android не подключается к локальному адресу автоматически. Этот API намеренно слушает только 127.0.0.1; локальный токен не заменяет Clerk для общедоступного сервера.

Документация: https://docs.rollypay.io/api/payments/ и https://fastapi.tiangolo.com/.
