# Vainah VPN — проверка Rollypay без настоящих денег

Сайт остаётся многостраничным, а кнопки покупки обычных тарифов ПОКА ведут в существующего Telegram-бота. Никаких реальных денег эта версия сайта не принимает.

## Что уже настроено владельцем в Netlify

- `ROLLYPAY_TERMINAL_ID` — есть.
- `ROLLYPAY_API_KEY` — есть, скрытый секрет.
- `ROLLYPAY_SIGNING_SECRET` — есть, скрытый секрет.

Не присылай значения этих переменных в чат, на скриншотах они должны быть закрыты.

## Что нужно добавить перед проверкой

В Netlify > Project configuration > Environment variables > Add a variable > Add a single variable:

**Key:** `ROLLYPAY_TEST_TOKEN`

**Value:** придумай личный длинный случайный пароль (не менее 24 символов). Используй менеджер паролей. Не копируй этот пароль из инструкции.

Включи **Contains secret values**, оставь **All scopes**, нажми **Create variable**.

Этот пароль нужен ТОЛЬКО тебе, чтобы посторонние не создавали тестовые счета на твоей кассе.

## Как разместить Netlify Functions (ВАЖНО)

Обычная повторная загрузка набора HTML-файлов через Netlify Drop — недостаточный способ для гарантированной установки Functions. Нужен Git-based deployment / полноценный build или Netlify CLI.

### Вариант с GitHub

1. Создай **приватный** репозиторий GitHub и помести в него **содержимое папки проекта**, чтобы в корне были `netlify.toml`, `package.json`, `site/` и `netlify/functions/`.
2. В Netlify открой существующий проект → Project configuration → Developer settings → Continuous deployment → Repository и подключи GitHub-репозиторий. Если интерфейс не позволяет привязать существующий сайт, НЕ создавай второй сайт с другими доменами без необходимости — сначала уточни способ переподключения.
3. При сборке Netlify должен обнаружить папку `netlify/functions` и опубликовать функции.
4. Убедись, что в Deploys есть статус `Published`, затем зайди на `https://ТВОЙ-ДОМЕН.netlify.app/admin-payment-check.html`.
5. Введи придуманный тестовый пароль и нажми «Создать тестовый платёж».
6. На тестовой платёжной странице должно быть обозначено, что это Sandbox. Настоящие деньги НЕ вводи и не отправляй.
7. После симуляции оплаты нажми «Проверить статус». Статус `paid` означает ТОЛЬКО успешный sandbox-тест.

Официальные инструкции Netlify: https://docs.netlify.com/build/functions/get-started/

## Webhook (только после публикации функций)

Endpoint, который проверяет подпись: 
`https://ТВОЙ-ДОМЕН.netlify.app/.netlify/functions/rollypay-webhook`

Для тестового события функция сверяет `X-Signature` с HMAC-SHA256 от `X-Timestamp + '.' + rawBody` и пишет безопасную краткую запись в Netlify function logs.

**Не устанавливай этот URL в действующую кассу с реальными клиентскими платежами до полной продакшен-интеграции.** Функция намеренно отвергает реальные платежи кодом HTTP 503: пока нет постоянной базы заказов, сверки реальной суммы/валюты, контроля повторов и выдачи H1Cloud. Из-за такого ответа реальные платежи не будут обработаны системой Vainah VPN.

## Для подключения реальных покупок ещё необходимы

- настоящие рублёвые цены тарифов и договорённость о составе услуг;
- постоянная БД заказов/пользователей (без неё нельзя безопасно учесть каждый платёж один раз);
- привязка заказа к конкретному владельцу VPN-подписки;
- серверный H1Cloud provisioning и проверка доступа пользователя;
- сверка `payment_id`, `order_id`, суммы, валюты, статуса и отмен/возвратов;
- идемпотентность — однократная выдача доступа;
- тестирование на sandbox и затем контролируемый запуск с учётом правил платёжного провайдера.

Для цифровых товаров/услуг **внутри Telegram Mini App** действуют требования оплаты через **Telegram Stars**. Rollypay здесь предназначен для самостоятельного сайта за пределами Telegram.

## Безопасный этап: вход через Telegram на основном сайте

На странице `site/account.html` появился личный кабинет с подтверждением Telegram ID через официальный Telegram Login Widget. Ссылка `account.html` добавлена на главную страницу.

Для входа в Netlify должны быть настроены:
- `PUBLIC_SITE_ORIGIN=https://vainahvpn.netlify.app`
- `TELEGRAM_BOT_TOKEN` — секретный токен собственного бота @Vainahvpn_bot;
- `SESSION_SIGNING_KEY` — случайный секрет длиной от 32 символов.

В @BotFather нужно привязать домен `vainahvpn.netlify.app` для Telegram Login Widget. Токен и ключ сессии не должны появляться в GitHub или скриншотах.

Здесь подключён **только Telegram-вход**: сервер проверяет HMAC-подпись и время авторизации и выдаёт HttpOnly-cookie. Новый защищённый API `my-subscription` может только читать срок подписки через H1Cloud по подтверждённому Telegram ID. При отсутствии настроек возвращается `panelReady:false`, деньги **не принимаются** на этой странице, VPN-ключи **не отправляются**. Старый RollyPay sandbox и уже работающий Telegram-бот не изменены.

Большая система с RollyPay и H1Cloud хранится в отдельной ветке `feature/telegram-linked-checkout` до отдельного тестирования и запуска. Не переносить её webhook или production checkout в рабочий сайт без проверки с владельцем и подтверждения действующих тарифов.


### H1Cloud — чтение действующей подписки без изменений клиентов

После настройки Netlify `PANEL_BASE_URL`, `PANEL_API_TOKEN` и `PANEL_CLIENT_PREFIX=tg` функция `/\.netlify/functions/my-subscription` делает **только GET** на API панели: `/api/clients/tg<Telegram ID>`. Она проверяет ответ `ok:true`, читает `client.expires_at` (Unix seconds) и возвращает браузеру только статус, дату и флаг блокировки. UUID, ссылки VLESS, список устройств и API-токен браузеру не передаются. `PANEL_BASE_URL` можно задавать без `/api` или с `/api`, функция нормализует адрес. Для доступа нужен вход через Telegram.

Если у существующего пользователя H1Cloud клиент называется не ровно `tg<Telegram ID>`, сервис не создаёт и не ищет произвольный профиль: показывает «не найден». Для дальнейшей интеграции с оплатой требуется отдельно проверить способ связать разные имена клиентов. RollyPay и H1Cloud provisioning **остаются отключёнными** на рабочем сайте.


### Проверка выдачи ссылки через Telegram (без оплаты)

На `account.html` у авторизованного пользователя с активным H1Cloud-профилем появилась кнопка «Отправить мой VPN в Telegram». Её POST-обработчик `send-my-vpn` проверяет `Origin` и signed session, ищет **только собственный** H1 профиль `PANEL_CLIENT_PREFIX + Telegram ID`, читает защищённый `sub_url`/`subscription_url` и отправляет его напрямую по Telegram Bot API в чат того же Telegram ID. Пользователю требуется заранее нажать `/start` у `@Vainahvpn_bot`. Ссылка, UUID и ключи не возвращаются браузеру и не логируются. Операция **не создаёт/продлевает VPN**, **не создаёт заказ**, **не вызывает платёжный API**. Это независимый тест связи с ботом, а не готовый платёжный checkout.


### RollyPay Sandbox: проверка без платежей и без H1Cloud изменений

На странице `/rollypay-sandbox.html` тест доступен только вошедшему владельцу:
1. `ROLLYPAY_API_KEY` — серверный ключ кассы в Netlify (**секрет**).
2. `VAINAH_SANDBOX_TELEGRAM_ID` — числовой Telegram ID владельца (его страница покажет после входа). Не публиковать как клиентский JS.
3. `SESSION_SIGNING_KEY` и `PUBLIC_SITE_ORIGIN` уже используются Telegram-входом.

Создание POST `/.netlify/functions/rollypay-sandbox` всегда отправляет `test:true` и демонстрационные `10.00 RUB` по `https://rollypay.io/api/v1/payments`. Ответ проверяется на `test:true` и `environment:"sandbox"` и точный разрешённый URL `https://pay.rollypay.io/pay/...`; иначе ссылка не открывается. Статус по API проверяется отдельным серверным POST с короткоживущим подписанным токеном, привязанным к Telegram ID. Нет базы заказов, нет выдачи ключей, продления/создания клиентов H1Cloud, никаких настоящих платежей.

После создания открой страницу RollyPay: если нет баннера «Тестовый режим», НЕ продолжай и ничего не оплачивай. На тестовой форме нажми «Симулировать успешную оплату», вернись на сайт и нажми «Проверить статус». Для настоящих денег нужна отдельная проверенная интеграция платежей и безопасные подписанные webhooks; старый секрет подписи вебхуков с опубликованного скриншота требуется перевыпустить.


#### Безопасная диагностика RollyPay sandbox

Если интерфейс показывает `[Код: PROVIDER_…]`, это код диагностики без токена, личных данных и ссылок: HTTP-ошибки проверяются *до* JSON-разбора, поэтому даже HTML-страница при ошибке авторизации не маскируется общей ошибкой формата. `PROVIDER_RESPONSE_NOT_JSON` означает, что сервис ответил на 2xx не-JSON; `PROVIDER_PAYMENT_ID_INVALID`, `PROVIDER_PAY_URL_INVALID` — несовместимый или небезопасный формат обязательных полей; `PROVIDER_SANDBOX_MISMATCH` — отсутствие строгого `test:true`, `environment:"sandbox"` или несовпадение ID/суммы. **Не копировать сырой HTTP-ответ и не снимать ограничения**. Настоящие покупки остаются отключены.


Sandbox `payment_id` считается непрозрачным ID RollyPay: поддерживаются ограниченные URL-safe строки, включая `pay_…`, UUID и ULID, без передачи сырого ID на клиент и без подстановки в URL вне фиксированного `GET /api/v1/payments/{id}`. Если `payment_id` отсутствует, диагностируется `PROVIDER_PAYMENT_ID_MISSING` без раскрытия тела ответа. Требования к `test:true`, `environment:sandbox`, точной сумме, `order_id` и владельцу Telegram неизменны.


Sandbox PayForm `pay_url`: документация RollyPay задаёт `https://pay.rollypay.io/pay/<token>` без требования обязательного префикса `tok_`. Валидатор проверяет HTTPS, точный домен, отсутствие userinfo/hash/query, один безопасный path-сегмент и максимальную длину. Для ошибочного ответа возвращаются только `PROVIDER_PAY_URL_MISSING`, `PROVIDER_PAY_URL_MALFORMED`, `PROVIDER_PAY_URL_UNSAFE_ORIGIN`, `PROVIDER_PAY_URL_UNEXPECTED_PATH`, без ссылок и токенов. Контроль `test:true` и `environment:sandbox` обязателен.

### Тестовая выдача после sandbox-оплаты (по умолчанию ОТКЛЮЧЕНА)

После успешного RollyPay sandbox теста сайт может создать один отдельный H1Cloud профиль на **1 день** и прислать ссылку через Telegram-бота. Для разрешения только этой операции добавь в Netlify:

- **Key:** `VAINAH_SANDBOX_H1_DELIVERY`
- **Value:** `enabled-test-only`

Для проверки уже нужны существующие секреты `PANEL_BASE_URL`, `PANEL_API_TOKEN`, `TELEGRAM_BOT_TOKEN`, `SESSION_SIGNING_KEY`, `ROLLYPAY_API_KEY` и числовой Telegram ID владельца в `VAINAH_SANDBOX_TELEGRAM_ID`. Секреты не копировать в сообщения, логи, GitHub и скриншоты.

На странице `/rollypay-sandbox.html` при возвращении из тестовой формы или ручном нажатии сервер читает RollyPay по короткоживущему подписанному proof. Если результат `paid` с `test:true`, `environment:"sandbox"` и верными order_id, payment_id, суммой и валютой, отдельное действие `deliver` **ещё раз** проверяет всё по API RollyPay. Только затем H1 получает `GET /api/clients/vainah_sbx_<ID>` и при отсутствии профиля — ровно `POST /api/create` с `days:1`, `device_limit:1`. Профили `tg<ID>` не затрагиваются; вызовов PATCH/DELETE нет, повторные проверки не прибавляют дни. Секретная VPN-ссылка отправляется через Telegram API только вошедшему владельцу, никогда не возвращается в браузер.

**Важно:** это владелец-only sandbox, а не платёжный продукт для клиентов. Без отдельной БД и безопасного callback мы не гарантируем однократность сообщения и не можем выдать VPN при полностью закрытом браузере. Возможна повторная отправка ссылки при повторной проверке, но не дополнительное продление. Для production нужны транзакционная база заказов, проверенная идемпотентность, повторная проверка событий и перевыпущенный ранее раскрытый webhook signing secret. `VAINAH_LIVE_CHECKOUT` остаётся выключенным.
