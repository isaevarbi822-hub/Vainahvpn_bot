# Vainah VPN — общая подписка сайта и Telegram (подготовлено, НЕ запущено)

## Что реализовано в ветке `feature/telegram-linked-checkout`

- `site/checkout.html` — покупка на **самостоятельном сайте во внешнем браузере**. Посетитель нажимает «Войти через Telegram», а не вводит непроверенный `@username`.
- Telegram Login Widget с запросом разрешения написать пользователю (`data-request-access="write"`), серверной HMAC-проверкой Telegram и подписанной HttpOnly cookie.
- `site/account.html` — личный кабинет: Telegram ID подтверждён через Telegram, срок подписки читается из настоящей H1Cloud-панели.
- `site/payment-result.html` — статусы заказа и доставки. Возврат с платёжной страницы НЕ означает, что деньги получены.
- Функции Netlify: создание заказа, платёжного счёта RollyPay, вебхук с проверкой подписи и контрольный запрос в API RollyPay.
- PostgreSQL база заказов с отдельным начислением срока и однократной записью `target_expires_at` для идемпотентности.
- Защищённая отправка личной VPN-ссылки через **того же** @Vainahvpn_bot после подтверждённой реальной оплаты и создания/продления профиля в H1Cloud.
- Ветка **не объединена с main**, поэтому текущий опубликованный сайт не меняется, а оплата **по умолчанию отключена**.

### Почему не просим просто @username?

Ник можно поменять или написать с ошибкой. Бот не может по одному нику надёжно отправить сообщение постороннему пользователю. Через Telegram Login Widget сайт получает подписанное `id`, проверяет его секретом бота, запрашивает разрешение на сообщения и сохраняет заказ за этим ID. Клиенту всё равно полезно один раз нажать **Start** в `@Vainahvpn_bot`; перед созданием реального платежа проверяется, доступен ли чат боту.

Официально: https://core.telegram.org/widgets/login/

## Требуется ДО включения реальной оплаты

1. **Восстановить доступный сайт Netlify.** Исправить текущий «Site not found» и выбрать окончательный HTTPS-домен. При переходе на новый аккаунт Netlify все секреты следует добавить заново в новый проект. Они НЕ переносятся автоматически.
2. Убедиться, что аккаунт RollyPay действительно подключён и позволяет принимать реальные платежи. Соблюдать возрастные требования, проверку личности и договоры провайдера; не пытаться обходить ограничения.
3. В **@BotFather** выполнить `/setdomain` для `@Vainahvpn_bot`: домен сайта должен точно совпадать с адресом, с которого показывается Telegram Login Widget.
4. Нужен **токен именно этого Telegram-бота** из @BotFather (`TELEGRAM_BOT_TOKEN`). Сохранять только как секрет Netlify. **Не изменять webhook текущего H1Cloud-бота**: отправка `sendMessage` по Bot API не требует перенастраивать обработчик обновлений.
5. Подключить транзакционную PostgreSQL базу данных и выполнить `database/subscriptions.sql`. Значение `DATABASE_URL` сохранить только в Netlify.
6. Из своей **панели H1Cloud VPN** получить `PANEL_BASE_URL`, `PANEL_API_TOKEN` и разрешённые `PANEL_INBOUND_IDS`. Токен панели отличается от API-ключа аккаунта H1Cloud вида `h1_...`. Без панели нельзя автоматически создать реальный VPN.
7. Уточнить, как существующий H1Cloud-бот называет клиентов. Подтверждённые существующие профили здесь названы `tg<Telegram ID>` (без подчёркивания): это настройка по умолчанию. **Если действующий бот хранит другие имена клиентов, общая подписка не будет синхронизирована без привязки этих записей.** Нельзя делать вид, будто базы H1Cloud-бота и сайта автоматически стали общей.
8. После проверки корректной привязки клиентов установить `PANEL_CLIENT_MAPPING_VERIFIED=true`. До этого сервер намеренно не принимает реальные заказы. Если бот использует другую схему имён, владелец может вручную установить `client_name` конкретному подтверждённому `telegram_id` в таблице `vpn_customers` после проверки владельца профиля. Ни в коем случае не угадывать чужие клиентские имена. Затем указать настоящие согласованные рублёвые цены тарифов 30, 90, 365 дней. Никаких придуманных сумм в коде нет.
9. Проверить весь сценарий на тестовой кассе RollyPay, включая успешный webhook, повторы, отмены и невозможность двойной выдачи. Провести ручной тест с собственным Telegram-аккаунтом и H1Cloud-профилем. Не проводить настоящую оплату до завершения тестов.
10. После проверки разработчиком/владельцем включить реальную оплату специально заданным флагом `VAINAH_LIVE_CHECKOUT=enabled-after-review`. До этого API возвращает 503 и кнопка покупки отключена.

### Переменные окружения Netlify

| Название | Что означает |
| --- | --- |
| `PUBLIC_SITE_ORIGIN` | Окончательный HTTPS origin сайта без завершающего слэша, например `https://yourproject.netlify.app` |
| `TELEGRAM_BOT_TOKEN` | Токен @Vainahvpn_bot; **секрет** |
| `SESSION_SIGNING_KEY` | Свой случайный секрет от 32 символов; **секрет** |
| `DATABASE_URL` | PostgreSQL URL; **секрет** |
| `ROLLYPAY_API_KEY` | API-ключ кассы; **секрет** |
| `ROLLYPAY_SIGNING_SECRET` | Секрет подписи webhook; **секрет** |
| `PANEL_BASE_URL` | URL своей H1Cloud VPN-панели, не кабинет аккаунта |
| `PANEL_API_TOKEN` | API-ключ VPN-панели; **секрет** |
| `PANEL_INBOUND_IDS` | Необязательные ID подтверждённых кастомных inbound; если не указаны, `/create` использует стандартные каналы H1Cloud |
| `PANEL_CLIENT_PREFIX` | Необязательный префикс, по умолчанию `tg` |
| `PANEL_CLIENT_MAPPING_VERIFIED` | `false` пока не проверено соответствие профилей H1 существующему боту |

| `VAINAH_PRICE_30_RUB` | Цена месячной подписки, строка вида `199.00` — **образец формата, не предложенная цена** |
| `VAINAH_PRICE_90_RUB` | Цена 90 дней |
| `VAINAH_PRICE_365_RUB` | Цена 365 дней |
| `VAINAH_LIVE_CHECKOUT` | По умолчанию `disabled`; включать лишь после полного аудита |

Все три цены требуются до включения. Прямо в GitHub реальные секреты НИКОГДА не записывать.

### RollyPay callback

Для **новой производственной интеграции** после всех проверок:

`https://ТВОЙ-РАБОЧИЙ-ДОМЕН/.netlify/functions/rollypay-live-webhook`

Прежний `/.netlify/functions/rollypay-webhook` остаётся тестовым и **намеренно отклоняет реальные платежи**. Не путать два адреса! Не устанавливать производственный callback в кассе до успешного тестирования всей цепочки.

### Общая подписка с Telegram-ботом

Общим реальным источником для VPN остаётся **H1Cloud-панель**:
- покупка на сайте → RollyPay → достоверная запись заказа → H1Cloud → уведомление в Telegram;
- оплата в боте → сам бот должен подтвердить Telegram Stars и обновить **тот же H1Cloud клиент**;
- страница `/account.html` читает реальный срок H1-профиля, если профиль имеет ожидаемое имя `tg_<ID>` (или настроен правильный префикс).

**Telegram:** VPN-подписки относятся к цифровым услугам. Внутри Telegram-ботов/Mini Apps действуют правила **Telegram Stars**. RollyPay используется только на независимом внешнем сайте. Platega не подключается к покупкам VPN внутри Telegram.

### Важные пределы и эксплуатация

- Если H1Cloud недоступен или пользователь заблокировал бота, подтверждённый заказ остаётся в базе с состоянием `retry`; повторная доставка не начисляет срок заново. Нужны мониторинг, резервные копии БД, ручная обработка таких заказов.
- Оспаривания и возвраты получают состояние `needs_review`; автоматический отзыв доступа требует отдельной политики и реализации.
- Следует ограничивать платёжные API, следить за логами и не печатать секреты/персональные ссылки в логах.
- Нельзя утверждать, что готовая версия уже принимает настоящие платежи или работает с конкретной живой H1Cloud-панелью: до настройки и тестов это **подготовленная интеграция**.

### Проверенный формат H1Cloud API

По исходникам H1Cloud клиент создаётся через `POST /api/create` с обязательными полями `name` и `days` (передавать только `expires_at` при создании нельзя). После создания целевая абсолютная дата закрепляется через `PATCH /api/clients/NAME` с `expires_at`. Существующие клиенты продлеваются тем же PATCH. Отсутствующий клиент — только точный JSON `{ok:false,error:"user_not_found"}`, другие 404 считаются ошибкой панели. Значение `PANEL_BASE_URL` допустимо без `/api` или с ним.

**Важно:** перед включением реальных платежей проверить эти операции на отдельном тестовом H1Cloud-клиенте и на тестовой кассе, не на действующих клиентах. Флаг платёжной активации остаётся отключённым, пока не проверены цены, база данных, выдача, повторы и требования провайдера к владельцу платежного аккаунта.
