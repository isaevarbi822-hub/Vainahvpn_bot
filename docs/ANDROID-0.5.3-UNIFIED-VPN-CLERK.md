# Vainah VPN 0.5.3 — восстановленная единая Android-сборка

Это **черновая тестовая версия**, а не проверенный выпуск VPN.

## Почему 0.5.2 не работала

APK 0.5.2 из шага `Android optional Clerk native SDK compile` включала
только `-PvainahEnableClerk=true`, но **НЕ** включала `-PvainahEnableLibbox=true`.
Из-за этого `EngineRegistry.active.ready` оставался `false` и приложение
не могло начать VPN-туннель. В APK также допускался выдуманный тестовый
публичный ключ Clerk, который не способен авторизовать пользователя.

## Что исправлено

- `0.5.3`: новый CI job собирает ОДИН APK с **двумя** флагами:
  `-PvainahEnableLibbox=true` и `-PvainahEnableClerk=true`.
- Настоящий публичный ключ Clerk обязателен до публикации APK. Фиктивный
  ключ не считается действующим и не даёт ложный экран входа.
- Проверка компиляции обоих SDK с синтетическим ключом запускается
  **без публикации файла для пользователей**.
- Превью ставится отдельным `app.vainah.vpn.preview` рядом с установленным
  `app.vainah.vpn`, чтобы не затереть рабочий VPN и его зашифрованную подписку.
  На превью придётся отдельно добавить HTTPS-ссылку подписки. Не удаляйте
  рабочую версию без резервной копии способа восстановления доступа.
- Отдельные реальные платежи по-прежнему запрещены. Без серверной проверки
  RollyPay / Clerk / H1Cloud / email счета не создаются.

## Что должен задать владелец Clerk

В `GitHub → Settings → Secrets and variables → Actions → Variables`
создать repository variable с именем:
`VAINAH_CLERK_PUBLISHABLE_KEY` и значением настоящего `pk_test_...`
или `pk_live_...` из **того же Clerk instance**, что используется на сервере.

**Никогда не вводите `CLERK_SECRET_KEY` / `sk_live_...` в Android,
публичную переменную или комментарий GitHub.** Публичный ключ `pk_` не
является секретом, но должен указывать на действующий Clerk instance.

После настройки потребуется повторить CI для ветки
`feature/android-clerk-libbox-unified-20261023`: только успешный job
`Android VPN engine + real Clerk auth APK` размещает ZIP-артефакт
`VainahVPN-0.5.3-Android-VPN-libbox-Clerk-preview`.

Также в Clerk Dashboard должны быть активированы способы входа и
настроена поддержка мобильного приложения для тестируемого Android
package `app.vainah.vpn.preview`, включая разрешённые возвратные
ссылки/домены по требованиям официального SDK.

## Минимальная проверка на Android-устройстве

1. Откройте экран Clerk, подтвердите вход и убедитесь, что после возврата
   в приложение отображается аккаунт.
2. Добавьте HTTPS-ссылку подписки H1Cloud, выберите сервер и включите VPN.
3. Проверьте интернет в браузере, внешнюю IP-локацию, DNS и IPv6;
   сам факт поднятия TUN **не доказывает**, что трафик защищён.
4. Выключите и повторно включите VPN, смените Wi-Fi/сотовую сеть, убедитесь,
   что есть кнопка отключения и нотификация Android.
5. При любой ошибке используйте предыдущую рабочую версию; публичный релиз
   и настоящую оплату не активировать до успешных тестов.

Функциональность Clerk, управление сессиями и libbox требуют испытаний на
реальном устройстве. Готовность компилятора не равна готовому продукту.
