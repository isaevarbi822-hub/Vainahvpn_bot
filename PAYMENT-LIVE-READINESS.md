# Vainah VPN — запуск реальной оплаты RollyPay (чек-лист)

**Статус: НЕ АКТИВИРОВАНО.** Этот документ и изменения в feature-ветке
не включают оплату, не изменяют сайт, клиентов H1Cloud или боевые платежи.
В `netlify/functions/lib/plan-catalog.mjs` функция `checkoutReady()`
намеренно возвращает `false`.

## Что уже есть

- Сайт создаёт заказ только после серверной авторизации владельца Telegram.
- Шесть тарифов и суммы хранятся на сервере; цена из браузера не принимается.
- RollyPay создаёт счёт с `test:false` только через серверную функцию.
- Подписанный webhook проверяется по HMAC, timestamp и сырым байтам тела.
- Статус, ID, RUB-сумма и валюта сверяются с независимым GET RollyPay,
  затем с сохранённым заказом в PostgreSQL.
- H1Cloud-профиль создаётся/продлевается только после подтверждения оплаты;
  абсолютный срок бронируется один раз, доставка повторяется идемпотентно.
- Отмены, истечение срока, возвраты и chargeback учитываются отдельно.
- Windows/macOS открывают оформление исключительно на официальном сайте,
  только когда сервер подтверждает готовность кассы.
- Android/iOS: внутри приложения нет приёма оплаты, до публикации требуется
  отдельная проверка применимых правил App Store/Google Play.

## До включения реального приёма платежей

1. **Законное владение кассой.** Сервис и кассу должен вести владелец, имеющий
   право на заключение договора и приём денег. Если разработчик несовершеннолетний,
   это должен согласовать и администрировать совершеннолетний законный владелец.
   Не обходить требования RollyPay, банков и магазинов приложений.
2. **Проверенные секреты только в Netlify** — `DATABASE_URL`,
   `ROLLYPAY_API_KEY`, `ROLLYPAY_SIGNING_SECRET`, `SESSION_SIGNING_KEY`,
   `TELEGRAM_BOT_TOKEN`, `PANEL_BASE_URL`, `PANEL_API_TOKEN`,
   `PUBLIC_SITE_ORIGIN`. Никаких значений в GitHub commits, Issue, chat,
   мобильных приложениях или браузерном JavaScript. Секрет тестового H1Cloud
   из GitHub Actions — отдельный и не годится для боевых платежей.
3. **Сайт и webhook.** Убедиться, что опубликованный URL совпадает с
   `PUBLIC_SITE_ORIGIN`, HTTPS работает и в RollyPay задан именно
   `https://<официальный-домен>/.netlify/functions/rollypay-live-webhook`.
   Подтвердить, что подпись проверяется и webhook отвечает вовремя.
4. **PostgreSQL.** Безопасно установить и проверить схему
   `database/subscriptions.sql`; проверить уникальность ID платежей и заказов,
   сохранение подтверждения, обработку повторных callback и recovery/reconcile.
5. **H1Cloud.** Отдельно проверить API-права, отображение срока подписки,
   создание тестового профиля, продление существующего пользователя,
   ограничения устройств и выдачу ссылки через авторизованный кабинет.
   Не запускать запись в боевые профили во время dry-run.
6. **Только sandbox и контролируемые тесты:** успешная/отклонённая оплата,
   неверная подпись, поддельные суммы, отсутствующий callback, повторный
   callback, задержка провайдера, возврат и ручное разрешение спорного заказа.
   Последние dry-run тесты: `payment-staging-safety.yml`.
7. **Публичные условия:** тарифы, сроки, возвраты, поддержка, юридические
   требования/налоги и политика обработки персональных данных — проверить
   со взрослым ответственным владельцем.
8. **Отдельный финальный запуск:** после независимого review и проверок
   нужен явный релиз и осознанное разрешение взрослого владельца. Одна
   настройка окружения не должна обходить hard-coded kill-switch.

## Не считать подтверждением оплаты

- Перенаправление браузера на страницу «Спасибо».
- Успешный ответ при создании счёта.
- Сообщение от клиента без подписанного webhook.
- Подписанный webhook, не сверенный с независимым API и суммой заказа.
- Успешные тесты GitHub без реальных проверок продакшн-кассы.

Webhook docs: https://docs.rollypay.io/api/callbacks/
